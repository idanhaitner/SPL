Systems Programming

Systems Programming (תכנות מערכות, 202-1-2031) is the course that takes a program apart into the machine it actually runs on. You draw stack and heap, write the special member functions a C++ class needs when it owns memory, then move to Java threads, sockets, the reactor, and a relational database. The exams keep returning to the same drawings: a copy that shares a buffer, a lock order that waits forever, a read that is not a whole message, and a list stored as one column instead of a table.

Where this shows up

Repeats on exams

The memory model

Draw the stack and the heap after a by-value call. The trap is putting the buffer on the stack, or drawing a by-value parameter as the same object as the caller's.

On an exam

Pointers and references

A repository of images behind a pointer array, returned by value from a local. The trap is treating the return as a copy of the pixels, or using sizeof of a pointer as a length.

Repeats on exams

Rule of three

A small class owns a raw array. Write the destructor and the deep copy. The trap is the default memberwise copy, or an assignment that frees the buffer before the new one exists.

Repeats on exams

Rule of five and zero

Steal a buffer, or delay the clone until a write. The trap is leaving the source pointer alive so two destructors free one block, or copying a unique_ptr.

Repeats on exams

Inheritance and polymorphism

Two derived types sit behind one base pointer. The call is non-virtual, the destructor is non-virtual, or an overload is used where an override was needed. The trap is a memory drawing that omits the vptr, or a delete through the base that skips the derived destructor.

Repeats on exams

Design by contract

Write the invariant and the preconditions and postconditions of a method. The trap is an invariant that forgets the empty case, or a postcondition that is only true when nobody else mutates the object.

Repeats on exams

Concurrency

A shared structure. Show a race, a deadlock, or a repair with synchronized, a semaphore, or an atomic. The trap is a lock order that waits forever, or protecting the update but not the read that publishes it.

Repeats on exams

Networking

Replace a delimiter with a length prefix, cap the clients, or write a small command protocol. The trap is treating a TCP read as a whole message, or forgetting that UDP has no accept.

Repeats on exams

The reactor

Edit the reactor from the appendix. Move tokenization off the selector, cap work per client, add a log, or serve a query without blocking select. The trap is a heavy call on the selector thread, or leaving OP_WRITE set so select spins.

Repeats on exams

Persistence and SQL

Design the tables, with a primary key, foreign keys, and a junction table for a many-to-many, then write one SELECT with a join. The trap is a Cartesian product with no join condition, or a list stored as columns instead of a junction table.
